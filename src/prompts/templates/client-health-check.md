Run a health check on the client `{{client}}` and tell me what's set up, what's missing and what's misconfigured. It is useful when onboarding a new client.

Use only free or near-free calls, one cheap check per source, and report each result as it is. If a source isn't set up or a check fails, say so; never assume it works.

1. **Find the client.** Call `list_clients`. Find the entry matching `{{client}}` (by `domain`, an alias, or its name). If there's none, say so, list the closest domains, and stop. Report, from its entry: `domain`, `name`, `sources`, `gscProperty`, `ga4PropertyId`, `missing`, `alternates` (other properties it could use), and whether it has `area`, `niche`, `brandTerms`, `competitors`, `trackedKeywords` and `keyPages` set. Then report the top-level `discovery` block: its `error`, `warnings`, `info` and `notes`. The `info` text includes which Google sign-in mode is in effect, and the `error` tells you if Google isn't set up at all. If I need to know which Google account is signed in for OAuth mode, tell me to run `crawlmark-cli auth status`, because no tool shows it. Use the entry's `domain` as the client for every call below.
2. **Search Console.** If the client has a `gscProperty`, call `gsc_query` with `client`, `dimensions: ["date"]` and `rowLimit: 5` (the default window is the last complete month). It works if rows or an empty result come back; an error is a failure, and I want the message. With no `gscProperty`, say "Search Console: not set up" and don't call it.
3. **GA4.** If the client has a `ga4PropertyId`, call `ga4_report` with `client`, `metrics: ["sessions"]` and `limit: 1`. Same rule. With no property, say "GA4: not set up" and don't call it.
4. **Chrome.** Call `render_check` with `url` set to `https://` plus the client's domain (the homepage). It's free and takes about 15 seconds. It proves headless Chrome launches and the site is reachable; also report any flags it raises (such as a title that only appears after JavaScript runs). If it fails to launch Chrome, say Chrome is unavailable, which also breaks Lighthouse, axe and `run_audit`; if it fails to fetch the site, say the site wasn't reachable.
5. **DataForSEO.** Call `dataforseo_status` (free, records no spend). Report whether the credentials work (`credentialsWork`: `true` works, `false` missing or rejected, `null` means the API couldn't be reached so they're untested, with `reachable: false`; say "couldn't check" for `null`, not "failing"), the `mode` (`sandbox` returns canned data and is not billed; `live` is real and billed) and the balance. Then call `spend_summary` (free) and report this month's paid spend for the client against the global cap (the client's own `monthlyBudgetUsd` is in its `list_clients` entry). If the credentials aren't set, say DataForSEO is unavailable and that Google-only reporting still works.
6. **Summarise.** Finish with a table: source (Search Console, GA4, Chrome, DataForSEO), status (working, failing, not set up, or not checked), and the one-line detail or error. Then a short "To fix" list in priority order, with the concrete next step for each (for example "set `gscProperty`", "run `crawlmark-cli auth login`", "set `DATAFORSEO_LOGIN` and `DATAFORSEO_PASSWORD` in `.env`", or "add key pages to clients.yaml"). If everything works, say that plainly.
