## CrUX History API [C1, C2, C3]

- `POST https://chromeuxreport.googleapis.com/v1/records:queryHistoryRecord?key=<API_KEY>`.
- Body: `origin` **or** `url` (one required); `formFactor` `PHONE` | `DESKTOP` | `TABLET` (omit for all); `metrics` (omit for all), e.g. `largest_contentful_paint`, `interaction_to_next_paint`, `cumulative_layout_shift`, `first_contentful_paint`, `experimental_time_to_first_byte`; `collectionPeriodCount` int, **min 1, max 40, default 25**.
- Response: `record.key` (`formFactor`, `origin`|`url`); `record.metrics.<m>.percentilesTimeseries.p75s[]` (one per period), `histogramTimeseries[]` (`start`, `end`, `densities[]`); `record.collectionPeriods[]` with `firstDate`/`lastDate` `{year, month, day}`, ascending, aligned with the arrays; `urlNormalizationDetails`.
- History: 40 weekly periods (about 10 months). Each period is a 28-day window, so periods overlap. Updated Mondays around 04:00 UTC with data through the previous Saturday; best effort, no SLA.
- Missing data: p75 is `null`, histogram densities are `"NaN"`.
- **CLS p75 values are strings** (e.g. `"0.05"`); parse with `Number()`.
- Key: a Google Cloud API key provisioned for the Chrome UX Report API. The existing `PSI_API_KEY` works only if that key's project has the Chrome UX Report API enabled and the key is not restricted to PageSpeed only (inference from C3).
- Quota: 150 queries per minute per Cloud project, shared with the daily CrUX API; free, cannot be raised by paying.
- Not documented: the status/body when an origin or URL has no data (the daily API returns 404 `NOT_FOUND`, per common usage; not confirmed in C1–C3).

## Bing Webmaster Tools API [B1–B4]

- Auth: API key (Settings → API Access → Generate API Key; one key per user, valid for all of that user's verified sites) or OAuth 2.0. **The key is sent as the `apikey` query parameter**, so a logged or cached URL leaks it.
- JSON endpoint: `GET https://ssl.bing.com/webmaster/api.svc/json/<Method>?siteUrl=<url>&apikey=<key>`. Responses wrap results in `{"d": ...}`. Dates are `"/Date(1316156400000-0700)/"`.
- Errors: HTTP 400 with `{"ErrorCode":3,"Message":"InvalidApiKey"}` (other codes not listed in B2).
- Read methods relevant to crawlmark: `GetUserSites()`, `GetRankAndTrafficStats(siteUrl)` (daily impressions/clicks), `GetQueryStats(siteUrl)` (top queries: `Query`, `Impressions`, `Clicks`, `AvgImpressionPosition`, `AvgClickPosition`, `Date`; "updated every week"), `GetPageStats(siteUrl)`, `GetQueryPageStats`, `GetPageQueryStats`, `GetCrawlStats(siteUrl)`, `GetCrawlIssues(siteUrl)`, `GetUrlInfo`, `GetLinkCounts`, `GetKeywordStats`.
- Write/side-effect methods that crawlmark must never call: every `Add*`, `Remove*`, `Submit*`, `Save*`, `Update*`, `Enable*`, `VerifySite`, and `FetchUrl` (asks Bing to fetch a URL).
- Cost: free. Rate limits are not documented in B1–B4.

Added in Stage C3 (2026-10-13, from B1, B2, B5–B7; still not exercised live):
- Key: Bing Webmaster Tools > **Settings** (top right) > **API Access** > accept the terms > **API Key** > **Generate API Key**. One key per user, valid for all of that user's verified sites; delete and regenerate it on the same page if it leaks (B1).
- Method shapes (B5). `GetUserSites` → `[{ Url, IsVerified, AuthenticationCode, DnsVerificationCode }]` (crawlmark keeps only `Url` and `IsVerified`). `GetRankAndTrafficStats(siteUrl)` → `[{ Date, Clicks, Impressions }]`, "updated every day", includes Web, Chat, News, Images, Videos and Knowledge Panel from 2023-03-24. `GetPageStats(siteUrl)` returns `QueryStats` rows whose `Query` is the page URL, updated weekly. `GetCrawlStats(siteUrl)` → `[{ Date, CrawledPages, CrawlErrors, InIndex, InLinks, Code2xx, Code301, Code302, Code4xx, Code5xx, BlockedByRobotsTxt, ContainsMalware, AllOtherCodes }]`, "for the last 6 months", updated daily. `GetCrawlIssues(siteUrl)` → `[{ Url, Issues, HttpCode, InLinks }]`; fixed issues can take a few days to disappear. `GetUrlInfo(siteUrl, url)` → one `UrlInfo` (`d` is an object, not an array); its JSON sample shows `url` quoted (`%22example.com%22`), so crawlmark doesn't use it yet.
- `Date` values are `/Date(ms±hhmm)/`: the milliseconds are UTC and the offset names the zone of the day, so `/Date(1316156400000-0700)/` is 2011-09-16.
- `ApiErrorCode` (B6): 0 None, 1 InternalError, 2 UnknownError, 3 InvalidApiKey, 4 ThrottleUser, 5 ThrottleHost, 6 UserBlocked, 7 InvalidUrl, 8 InvalidParameter, 9 TooManySites, 10 UserNotFound, 11 NotFound, 12 AlreadyExists, 13 NotAllowed, 14 NotAuthorized, 15 UnexpectedState, 16 Deprecated. Errors come back as HTTP 400 with `{"ErrorCode":n,"Message":"..."}` (B2). crawlmark treats 3, 6 and 10 as a key problem, retries 4, 5, 1 and HTTP 5xx/429 once, and reports 7, 13 and 14 as a site the key can't read.
- `CrawlIssues` (B7) is a flags enum: 1 Code301, 2 Code302, 4 Code4xx, 8 Code5xx, 16 BlockedByRobotsTxt, 32 ContainsMalware, 64 ImportantUrlBlockedByRobotsTxt, 128 DnsErrors, 256 TimeOutErrors (the JSON sample shows a number, the XML sample a name).

## DataForSEO Labs: keyword ideas and keyword gap [D1–D3]

- `POST /v3/dataforseo_labs/google/keyword_ideas/live`: `keywords` (up to 200 seeds), `location_code`, `language_code`, `limit` (default 700, max 1000), `filters`, `order_by` (default `relevance,desc`), `closely_variants`, `ignore_synonyms`, `include_serp_info`, `include_clickstream_data` (doubles the price). Items: `keyword`, `keyword_info.{search_volume, cpc, competition, competition_level}`, `keyword_properties.keyword_difficulty` (0–100), `search_intent_info.main_intent`.
- Sibling endpoints with the same item shape and price: `keyword_suggestions/live` (keywords containing the seed; one seed) and `related_keywords/live` ("searches related to"). Their parameters were not re-read for this doc; see Not confirmed.
- `POST /v3/dataforseo_labs/google/domain_intersection/live`: `target1`, `target2` (no scheme, no `www.`), `location_code`, `language_code`, `intersections` (default `true`; **`false` returns keywords `target1` ranks for and `target2` does not**, with data for `target1` only), `item_types` (default `["organic","paid"]`), `limit` (default 100, max 1000), `filters`, `order_by` (default by search volume). Items: `keyword_data.keyword`, `keyword_data.keyword_info.search_volume`, `first_domain_serp_element` (with `rank_absolute`, URL), `second_domain_serp_element`.
- Price (D3): **$0.012 per task + $0.00012 per item** (Live), for every Labs Google endpoint not listed as an exception; none of the above is an exception. `include_clickstream_data` doubles it.
- Limits: 2,000 calls/min, 30 simultaneous, one task per Live call.

Price (D6): **$0.00075 per 10 reviews in the standard queue (up to 45 minutes), $0.0015 per 10 in the priority queue (up to 1 minute)**. A search operator in `keyword` multiplies the price by 5. Review item fields are on the task_get page (not read).
- **Google Maps SERP, Live:** `POST /v3/serp/google/maps/live/advanced`. `keyword`, location (`location_coordinate` "lat,lng,zoom"), `language_code`, `depth` (default 100, max 700; above 100 may cost more), `device`. Items `maps_search`: `rank_group`, `rank_absolute`, `title`, `domain`, `url`, `rating`, `place_id`, `cid`, `address`, `category`, `is_claimed`. Billed per SERP of up to 100 results; example **$0.002**.
- The Google Business Profile API itself is not used: it needs Google approval (landscape doc).

Added in Stage C4 (2026-10-13, from D4, D7, D14-D16; still not exercised live):
- My Business Info `location_coordinate` is "lat,lng,radius" (radius 199.9 to 199999), unlike Maps' "lat,lng,zoom". Items are `type: "google_business_info"`; besides the fields above they carry `work_time.work_hours.timetable` (per weekday, arrays of `open`/`close` `{hour, minute}`, plus `current_status`), `place_topics` (review keywords with counts; can contain reviewer-chosen words), `people_also_search` (other businesses) and `directory`. crawlmark keeps business facts only (D4).
- Reviews `task_post`: one of `keyword`, `cid` or `place_id`; `sort_by` defaults to `relevant`; `priority` 1 (default) or 2 (faster, costs more); the example task with depth 50 cost $0.00375 (standard queue: 5 × $0.00075). A successful post is task status 20100 "Task Created." with `result: null` (D15).
- Reviews `task_get`: `GET /v3/business_data/google/reviews/task_get/<id>`, free within 30 days. Result `type: "google_reviews"` with `title`, `sub_title`, `rating`, `reviews_count`, `place_id`, `cid`, `items[]`. Items are `type: "google_reviews_search"` with `review_text`, `original_review_text`, `original_language`, `time_ago`, `timestamp` ("2019-11-15 12:57:46 +00:00", UTC), `rating {value, votes_count, rating_max}`, the reviewer's `reviews_count`, `photos_count`, `local_guide`, `profile_name`, `profile_url`, `profile_image_url`, `review_url`, `review_id`, `owner_answer`, `original_owner_answer`, `owner_time_ago`, `owner_timestamp`, `review_highlights` and `images[]`. The docs' own owner-reply example names the reviewer, so crawlmark returns `owner_answer` only as a yes/no and drops every reviewer field (D14).
- A task that isn't ready answers task status 40601 "Task Handed" or 40602 "Task In Queue" (D16); crawlmark treats those two as "pending" and every other status >= 40000 as an error.
- Maps `maps_search` items also have `rating_distribution`, `work_hours`, `phone`, `total_photos` and `local_justifications` (D7); crawlmark keeps rank, title, domain, rating, votes, place_id and cid.

## Ahrefs API v3: keyword ideas and gap inputs [A1]

- `GET /v3/keywords-explorer/matching-terms`: `keywords` (comma list), `country` (required), `terms` `all` | `questions`, `match_mode` `terms` | `phrase`, `select`, `where`, `order_by`, `limit` (default 1000, max 150000).
- `GET /v3/keywords-explorer/related-terms`: same plus `terms` `all` | `also_rank_for` | `also_talk_about`, `view_for` `top_10` | `top_100`.
- Field costs (both): `volume` 10, `difficulty` 10, `traffic_potential` 10, `intents` 10 units; `keyword`, `cpc`, `parent_topic` carry no cost label (1 unit each per `docs/research/ahrefs-api-v3.md` A4's default). `select=keyword,volume,difficulty,cpc` = **22 units per row**, with the 50-unit minimum per request.
- No keyword-gap endpoint exists in the OpenAPI spec. A gap is built from `site-explorer/organic-keywords` per competitor (`select=keyword,best_position,best_position_url,volume` = 1+1+1+10 = **13 units per row**) minus the client's own rankings.

## Semrush API v3: keyword ideas and gap [S1, S2]

- `type=phrase_fullsearch` (Broad Match): **20 units per line**; `phrase_related`: **40 units per line**; `phrase_questions`: **40 units per line**. One `phrase` per request; `display_limit` defaults to 10,000 lines (always send it; see `docs/research/semrush-api.md`). Columns `Ph, Nq, Cp, Co, Kd` (and `Rr` for related).
- `type=domain_domains` (Domain vs Domain): `domains` is `<sign>|<or|ad>|<domain>` joined by `|`; signs `*` (shared), `+` (all), `-` (exclude), `/` (only in one). **Keywords `A` has that `B` lacks: `*|or|A|-|or|B`.** Up to five domains. Columns `Ph, P0, P1, ..., Nq, Cp, Co, Kd`. **80 units per line** (400 for historical).

## Google crawler IP ranges [G1]

- `https://developers.google.com/static/crawling/ipranges/common-crawlers.json` (Googlebot), `special-crawlers.json`, `user-triggered-fetchers.json`. Reverse DNS alternative: host ends in `googlebot.com`, `google.com` or `googleusercontent.com`, and resolves forward to the same IP.

A `.docx` is a ZIP of a handful of XML parts (`[Content_Types].xml`, `_rels/.rels`, `word/document.xml`, `word/styles.xml`, `word/_rels/document.xml.rels`, optional `word/media/*` and `word/numbering.xml`). Node 22.13+ ships `zlib.crc32` and `deflateRawSync`, so a ZIP writer is about 80 lines. The report is a small block model (headings, paragraphs, bullet lists, tables, key-figure rows, an optional logo), so the WordprocessingML needed is small and fully under crawlmark's control.

## Google Drive handoff [M1]

Claude's Drive connector `create_file` takes `title` (required), `textContent` (UTF-8) or `base64Content`, `contentMimeType` (required with content), optional `parentId`, and `disableConversionToGoogleType` (default false: supported content is converted to Google Docs). `text/html` content becomes a Google Doc with tables; Markdown import exists in Google Docs (landscape doc). crawlmark never calls Drive; the model does, with the user's consent.
