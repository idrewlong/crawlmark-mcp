## llms.txt format (L1)

The file is Markdown, in this order:

1. An H1 with the project or site name. This is the only required part.
2. Optionally, a blockquote with a short summary.
3. Optionally, more Markdown of any kind except headings (paragraphs, lists).
4. Zero or more H2 sections, each a "file list": Markdown list items of the form `[name](url)`, optionally followed by `: notes`.
5. An H2 named `Optional` is special: its links can be skipped when a shorter context is needed.

The proposal also covers `.md` versions of pages and `rel="describedby"` discovery. `/llms-full.txt` isn't in the proposal text. It's a common companion (the whole content in one file), so crawlmark only reports whether it's there, its status, type and size, and doesn't check its format.

How crawlmark applies this: only the structure can be an issue: no H1, content before the H1, more than one H1, a heading other than H1/H2 before the first H2, and H2 sections without any links. Real files vary a lot in how they write list items, so any top-level list item under an H2 (`-`, `*`, `+`, `1.` or `1)`) whose content starts with a Markdown link counts as a link, whatever follows it: `: notes` (the proposal's form), `- notes` or an em dash, a bold `**[name](url)**`, a link title (`[name](url "title")`), an angle-bracket URL (`[name](<url>)`) and URLs with one level of balanced parentheses (`Foo_(bar)`). Indented sub-bullets are ignored. List items that don't start with a link, and the style of notes, are kept as counts (`nonLinkItems`, `notesStyle`), not issues. Fenced code is skipped.

**Google (G1):** "You don't need to create new machine readable files, AI text files, markup, or Markdown to appear in Google Search", and keeping llms.txt files for other services "will neither harm nor help your site's visibility or rankings in Google Search, as Google Search ignores them." So crawlmark reports llms.txt for information only. A missing file is not a finding, and problems are only ever `low`.

## AI crawler tokens

| Token | Vendor | Purpose in crawlmark | Source and notes |
|---|---|---|---|
| `OAI-SearchBot` | OpenAI | search | O1: sites that opt out of it "will not be shown in ChatGPT search answers" |
| `ChatGPT-User` | OpenAI | user (robots.txt may not apply) | O1: user-initiated, "robots.txt rules may not apply"; not used for search inclusion |
| `GPTBot` | OpenAI | training | O1: disallowing it means content "should not be used in training generative AI foundation models" |
| `Claude-SearchBot` | Anthropic | search | A1: blocking it "may reduce your site's visibility" in search results |
| `Claude-User` | Anthropic | user | A1: user-directed fetches; Anthropic's bots honour robots.txt |
| `ClaudeBot` | Anthropic | training | A1: collects content that could contribute to training |
| `anthropic-ai` | Anthropic | training (legacy) | Not in A1 any more. Still common in robots.txt files, so it's listed; treat it as a legacy opt-out token |
| `PerplexityBot` | Perplexity | search | P1: surfaces sites in Perplexity search; "not used to crawl content for AI foundation models" |
| `Perplexity-User` | Perplexity | user (robots.txt generally ignored) | P1: "this fetcher generally ignores robots.txt rules" |
| `Google-Extended` | Google | training (token only) | G2: no separate user agent; covers Gemini training and grounding; "does not impact a site's inclusion in Google Search" |
| `Applebot-Extended` | Apple | training (token only) | AP1: "does not crawl webpages"; pages that disallow it "can still be included in search results" |
| `CCBot` | Common Crawl | training | CC1: open crawl corpus widely used for training; blocked with `User-agent: CCBot` |
| `Bytespider` | ByteDance | training | No primary ByteDance documentation found. Third-party sources describe it as collecting data for ByteDance's models. Listed because it's common in robots.txt files |
| `Meta-ExternalAgent` | Meta | training | M1: crawls for "training foundation AI models or improving products by indexing content directly"; honours robots.txt |
| `Amazonbot` | Amazon | training | AM1: "may be used to train Amazon AI models". Amazon's search and Alexa-answer agents are `Amzn-SearchBot` and `Amzn-User`, which aren't in the table yet |

**Findings.** Blocking a `search` crawler, or a `user` crawler whose vendor says it honours robots.txt (Claude-User), from the homepage or a key page is a `low` `ai-search-crawler-blocked` finding worded "if this is intended, ignore it". Blocks of `training` crawlers, and of user fetchers that may ignore robots.txt (ChatGPT-User, Perplexity-User), are data only. A `*` group that blocks everything (`robots-disallow-all`), or that blocks a key page for Googlebot too (`robots-blocks-key-page`), is already reported, so it isn't reported again.

**bots.ts (log analysis).** The same names are used. `Amazonbot` moved from `other` to `ai-training` to match AM1. `anthropic-ai` and `Applebot-Extended` are robots.txt tokens only and are not in the log table (Google-Extended is listed there as a token-only row).
