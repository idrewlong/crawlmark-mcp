## General

**Facts**

- **Access and plans** [S2]:
  - The Standard API (SEO API) needs an SEO Toolkit **Business** subscription, plus a separately bought **API unit package**.
  - Right after the upgrade to Business, the unit balance is still zero.
  - Units are bought under Subscription info > API Units.
  - Every Semrush API needs an eligible paid subscription.
- **Two key types.** This matters for crawlmark.
  - "For Version 3 methods, you'll need a v3 API key" [S2].
  - "Version 3 APIs use Version 3 API keys" and take them as the `key` query parameter [S3].
  - "SEO API in Version 4 requires a Version 4 API key" [S11].
  - "Your account includes one autogenerated v4 key", and new v4 keys can be created with Read-only or Read and write permission [S4].
  - v4 accepts `Authorization: Apikey <YOUR_API_KEY>` (recommended) or `?key=` [S4].
  - Rotation differs by version [S2]. A lost v4 key is replaced by the user (create a new one, revoke the old). A lost v3 key needs Semrush Tech Support.
- **Where the v3 key is.** "Subscription info > API units" [S7, S8 param tables], or "the API keys section of your Semrush profile" [S2, S3].
- **Rate limits** [S6]:
  - 10 requests per second.
  - 10 simultaneous requests per account.
  - Standard API use is also bounded by the unit balance.
- **Caching rule** [S6]. API data may not be cached for more than one month without Semrush's written consent.
- **Units** [S5]:
  - Reports are priced either per line returned (for example Domain reports) or per request (for example Backlinks overview).
  - Historical data, requested with `display_date`, costs more.
  - **"Do empty API responses consume API units? No. Requests that return no data don't consume API units."**
  - When units run short: "In SEO API … you'll get ERROR 132". Also: "In SEO API and Trends API, for reports that cost per line, you will get the number of lines for which you have enough API units", meaning **partial results**.
  - Under My Profile → Query log → API Queries, the UI shows the units spent on each request. Semrush documents no per-response unit header.
- **v3 response format** [S7].
  - "All SEO API report endpoints return responses in CSV format": semicolon-separated, with a header row.
  - **The header row uses display names, not column codes.** For example `Keyword;Search Volume;CPC;…` for `Ph,Nq,Cp,…` [S8, S9 examples].
  - Column rules [S7]: "Column names can't be changed. The order of columns can be changed. The number of columns can be increased."
  - `export_escape=1` wraps each column in double quotes [S8, S9].
- **v3 errors** [S7]. The body is plain text in the form `ERROR <n> :: <MESSAGE>`. The codes crawlmark must handle:

  | Code | Text | Meaning |
  |---|---|---|
  | 40–46 | `MANDATORY PARAMETER <x> NOT SET OR EMPTY` | a required parameter is missing (40 action, 41 type, 42 domain, 43 phrase, 44 url, 46 database) |
  | 50 | `NOTHING FOUND` | no data for the request |
  | 110 | `INVALID IMPORT KEY` | the key has the wrong format |
  | 120 | `WRONG KEY - ID PAIR` | unknown key |
  | 130 | `API DISABLED` | the subscription doesn't include the API |
  | 131 | `LIMIT EXCEEDED` | the per-report request limit was reached |
  | 132 | `API UNITS BALANCE IS ZERO` | no units left |
  | 133 | `DB ACCESS DENIED` | no access to that database |
  | 134 | `TOTAL LIMIT EXCEEDED` | the total request limit was reached |
  | 135 | `API REPORT TYPE DISABLED` | the report was retired or the subscription ended |
  | 402 | `Request param not valid` | the key is incorrect |
  | 429 | `Too Many Requests` | rate exceeded |
  | 500 | `Internal Error` | |
  | 605 | invalid `display_offset` | |
  | 613 | too many rows requested | |
  | 10000–10040 | `Wrong parameter '<p>'. <description>.` | parameter validation |

- **v4 errors** [S11]. The body is JSON:

  ```json
  { "meta": { "success": false, "status_code": 403, "request_id": "…" },
    "error": { "code": 403, "message": "Forbidden", "retryable": false, "details": {} } }
  ```

  The documented statuses are 400, 401 (authentication failed or credentials missing), 403 (no permission), 404, 409, 429, 499, 500, 501, 503 and 504.
- **Databases** [S7].
  - Lowercase two-letter codes. **The United Kingdom is `uk`**, and the US is `us`.
  - Mobile databases (`mobile-` prefix) and extended ones (`-ext` suffix) are not available in Keyword reports.
  - The documented desktop list: us uk ca ru de fr es it br au ar be ch dk fi hk ie il mx nl no pl se sg tr jp in hu af al dz ao am at az bh bd by bz bo ba bw bn bg cv kh cm cl co cr hr cy cz cd do ec eg sv ee et ge gh gr gt gy ht hn is id jm jo kz kw lv lb lt lu mg my mt mu md mn me ma mz na np nz ni ng om py pe ph pt ro sa sn rs sk si za kr lk th bs tt tn ua ae uy ve vn zm zw ly pa pk tw qa.
- **Deprecations** [S1, v3 index]:
  - The v3 Keyword reports API is deprecated in favour of v4 Keyword reports.
  - The v3 Backlinks API is deprecated in favour of v4 Backlinks.
  - Both are "still operational, but not recommended for new integrations".
  - The v3 Domain reports (`domain_organic`, `domain_organic_organic`) are **not** deprecated and have no v4 equivalent ("Some APIs and methods are available only in v3").

**Inference**

- A user who wants every Semrush capability in crawlmark needs **both** keys: the v3 key for domain reports, and the v4 key for v4 backlinks or v4 keyword metrics. With only the v3 key, the deprecated v3 keyword and backlinks reports still work today.
- Partial results when units are low are silent: the documentation describes no marker. A response with fewer lines than `display_limit` can mean "that's all the data" or "units ran out".

## Endpoints

### Free key check: `GET http://www.semrush.com/users/countapiunits.html?key=<key>`

**Facts** [S5]

- Documented with `http://`.
- The `key` parameter is "assigned to each user after subscribing … You'll find it in Subscription info > API units".
- It returns the remaining API units.
- The documented response example is the plain text `1,000`.
- It is listed under "free API requests". The Trends limits endpoint on the same page says "Price: 0 API units per request". The Standard one only says it is free.

### `type=phrase_these`: Batch Keyword Overview (keyword volume; v3, deprecated)

**Facts** [S9]

- **Request.** `GET https://api.semrush.com/`, priced at **10 units per line** (50 per line for historical data).
- It summarises "up to 100 keywords" in one database.
- **Parameters.**

  | Parameter | Required | Value |
  |---|---|---|
  | `type` | yes | `phrase_these` |
  | `key` | yes | the v3 key |
  | `phrase` | yes | keywords separated by `;` |
  | `database` | yes | a database code |
  | `export_columns` | no | from `Ph, Nq, Cp, Co, Nr, Td, In, Kd`; the default is `Ph,Nq,Cp,Co,Nr,Td` |
  | `export_escape` | no | `1` |
  | `export_decode` | no | `1` or `0` |
  | `display_date` | no | `YYYYMM15`; omit it for current data |

- **Columns** [S7]:

  | Code | Header text | Meaning |
  |---|---|---|
  | `Ph` | Keyword | the keyword |
  | `Nq` | Search Volume | average monthly searches over the last 12 months |
  | `Cp` | CPC | average USD per click (dollars, not cents) |
  | `Co` | Competition | advertiser competitive density, 0–1 |

- **Documented example (verbatim)**:

  ```
  https://api.semrush.com/?type=phrase_these&key=API_KEY&phrase=ebay;seo&export_columns=Ph,Nq,Cp,Co,Nr,Td&database=us
  Keyword;Search Volume;CPC;Competition;Number of Results
  ebay;45500000;0.54;0.01;1880000000
  seo;110000;14.82;0.5;678000000
  ```

  The request asks for `Td`, but the documented response has no Trends column. The doc's own example is inconsistent.

### v4 Keyword Metrics (the replacement for phrase_these; not used in Phase 9)

**Facts** [S13]

- **Request.** `GET https://api.semrush.com/apis/v4/keywords/v1/metrics`, priced at **20 units per request**, **one keyword per request**.
- **Parameters.**
  - `keyword` (required, 1–255 characters).
  - `country` (required, *uppercase* alpha-2; the supported list uses `UK`, not `GB`).
  - `month` (`YYYY-MM`, default the current month).
  - `format` (`json` by default, or `csv`).
- **Response.** `data.search_volume` (a string; the 12-month average), `data.cpc` (a string, in USD **cents**), `data.competitive_density` (0–100), `keyword_difficulty`, `intents`, `serp_features` and `trends`.
- **Documented example (excerpt)**:

  ```json
  { "meta": { "country": "US", "keyword": "seo tools", "month": "2024-01", "status_code": 200, "success": true },
    "data": { "competitive_density": 78, "cpc": "1245", "search_volume": "60500", "keyword_difficulty": 74 } }
  ```

### `type=domain_organic`: Domain Organic Search Keywords (ranked keywords; v3)

**Facts** [S8, S7]

- **Request.** `GET https://api.semrush.com/`, priced at **10 units per line** (50 per line for historical data).
- **Parameters.**

  | Parameter | Required | Value |
  |---|---|---|
  | `type` | yes | `domain_organic` |
  | `key` | yes | the v3 key |
  | `domain` | yes | the domain |
  | `database` | yes | a database code |
  | `display_limit` | no | **unset or 0 returns 10,000 lines by default**; at most 100,000 lines per response; the maximum value is 4,000,000 |
  | `display_offset` | no | lines to skip |
  | `export_columns` | no | from `Ph, Po, Pp, Pd, Nq, Cp, Ur, Tr, Tg, Tc, Co, Nr, Td, Kd, Fp, Fk, Ts, In, Pt`; the default is `Ph,Po,Pp,Pd,Nq,Cp,Ur,Tr,Tc,Co,Nr,Td` |
  | `display_sort` | no | `po_asc/desc`, `tg_*`, `tr_*`, `tc_*`, `nq_*`, `co_*`, `kd_*`, `cp_*`, `nr_*`, `ts_*` |
  | `display_date` | no | |
  | `display_daily` | no | |
  | `display_positions` | no | |
  | `display_positions_type` | no | `organic` (default), `all` or `serp_features` |
  | `display_filter` | no | |
  | `export_escape` | no | |

- **Columns** [S7]:

  | Code | Header text | Meaning |
  |---|---|---|
  | `Po` | Position | 0–100, where 0 means not ranked |
  | `Ur` | Url | the ranking URL |
  | `Tr` | Traffic (%) | a *share*, not visits |
  | `Tg` | Traffic | "amount of estimated organic traffic driven to an analyzed domain with a given keyword" |
  | `Nq`, `Ph` | | as above |

- **Documented example (verbatim; first three lines)**:

  ```
  https://api.semrush.com/?type=domain_organic&key=YOUR_API_KEY&display_filter=%2B%7CPh%7CCo%7Cseo&display_limit=10&export_columns=Ph,Po,Pp,Pd,Nq,Cp,Ur,Tr,Tc,Co,Nr,Td&domain=seobook.com&display_sort=tr_desc&database=us
  Keyword;Position;Previous Position;Position Difference;Search Volume;CPC;Url;Traffic (%);Traffic Cost (%);Competition;Number of Results;Trends
  seo;9;10;1;110000;14.82;http://www.seobook.com/;17.53;44.40;0.50;0;0.81,1.00,1.00,1.00,1.00,0.81,0.81,0.81,0.81,0.81,0.81,0.81
  seobook;1;1;0;1300;4.54;http://www.seobook.com/;5.52;4.28;0.32;379000;0.62,0.81,0.62,0.81,0.81,0.62,0.62,0.81,0.81,0.62,1.00,0.81
  ```

  The Trends column itself contains commas. Fields are separated by `;` only.

### `type=domain_organic_organic`: Competitors in Organic Search (v3)

**Facts** [S8, S7]

- **Request.** `GET https://api.semrush.com/`, priced at **40 units per line** (200 per line for historical data).
- **Parameters.**

  | Parameter | Required | Value |
  |---|---|---|
  | `type` | yes | `domain_organic_organic` |
  | `key` | yes | the v3 key |
  | `domain` | yes | the domain |
  | `database` | yes | a database code |
  | `display_limit` | no | the same 10,000-line default when unset |
  | `display_offset` | no | |
  | `export_columns` | no | from `Dn, Cr, Np, Or, Ot, Oc, Ad, Sr, St, Sc`; the default is `Dn,Cr,Np,Or,Ot,Oc,Ad` |
  | `display_sort` | no | `np_desc`, `np_asc`, `cr_desc`, `cr_asc` |
  | `display_date`, `export_escape`, `export_decode` | no | |

- **Columns** [S7]:

  | Code | Header text | Meaning |
  |---|---|---|
  | `Dn` | Domain | the competitor |
  | `Np` | Common Keywords | shared top-100 keywords |
  | `Ot` | Organic Traffic | the competitor's organic traffic |
  | `Cr` | Competitor Relevance | relevance score |

- **Documented example (verbatim; first two lines)**:

  ```
  https://api.semrush.com/?type=domain_organic_organic&key=YOUR_API_KEY&display_limit=10&export_columns=Dn,Cr,Np,Or,Ot,Oc,Ad&domain=seobook.com&database=us
  Domain;Competitor Relevance;Common Keywords;Organic Keywords;Organic Traffic;Organic Cost;Adwords Keywords

  ```

### v4 Backlinks Overview: `GET https://api.semrush.com/apis/v4/backlinks/v1/overview`

**Facts** [S12, S11]

- **Price.** **45 units per request.**
- **Auth.** A v4 key.
- **Parameters.**
  - `url` (required, up to 2000 characters, with or without the protocol).
  - `scope` (required: `ROOT_DOMAIN`, `SUBDOMAIN`, `SUBFOLDER` or `PAGE`).
  - `fields` (optional; all fields by default).
  - `format` (`json` by default, or `csv`).
- **Response** `data` fields:
  - `backlinks_count` and `domains_count` (referring domains);
  - `new_count` (first seen within 30 days) and `lost_count`;
  - `score`: "For URL scope: page score. For all other scopes: domain score (0–100)";
  - `follows_count`, `nofollows_count`, `urls_count`, `ips_count`, `ip_class_c_count`, `texts_count`, `images_count`, `forms_count`, `frames_count`, `sponsored_count` and `ugc_count`.
- **Documented example (verbatim excerpt)**:

  ```json
  { "meta": { "request_id": "4fb1773ec2a8d61a0407f464599f897c", "status_code": 200, "success": true },
    "data": { "backlinks_count": 2341, "domains_count": 156, "lost_count": 15, "new_count": 23, "score": 78,
              "follows_count": 1823, "nofollows_count": 518, "urls_count": 267 } }
  ```

### v3 Backlinks Overview (deprecated): `GET https://api.semrush.com/analytics/v1/?type=backlinks_overview`

**Facts** [S10]

- **The path is `/analytics/v1/`, not `/`.**
- **Price.** **40 units per request.**
- **Parameters.**
  - `type=backlinks_overview` and `key` (required).
  - `target` (required: a root domain, subdomain or URL).
  - `target_type` (required: `root_domain`, `domain` or `url`).
  - `export_columns`, marked Required. The allowed values are `ascore, total, domains_num, urls_num, ips_num, ipclassc_num, follows_num, nofollows_num, sponsored_num, ugc_num, texts_num, images_num, forms_num, frames_num`.
- **Documented example (verbatim; columns trimmed to the ones crawlmark uses)**:

  ```
  https://api.semrush.com/analytics/v1/?key=YOUR_API_KEY&type=backlinks_overview&target=searchenginejournal.com&target_type=root_domain&export_columns=ascore,total,domains_num,…
  ascore;total;domains_num;…
  74;22063983;49145;…
  ```

- There are no `new`/`lost` counts in v3 overview.

## Inference (not stated by Semrush)

- `Tg` is the visits estimate that crawlmark's `estimatedTraffic` wants. `Tr` is a percentage and must not be used for it.
- Asking for an extra column doesn't change the per-line price, because prices are quoted per line, not per column.
- A v3 error body probably comes with HTTP 200. Older integrations parse the `ERROR` prefix rather than the status code. The docs don't say.
- **Always send `display_limit`**, because leaving it out bills up to 10,000 lines. For `domain_organic` that is 100,000 units.
- Map CSV columns by position, using the `export_columns` order crawlmark sent, and check the header text against the code-to-header table above. Never key on the header text alone.

## Not confirmed

1. Whether `https://www.semrush.com/users/countapiunits.html` works. Only `http://` is documented, and sending the key over plain HTTP is not acceptable.
2. The exact format of the countapiunits body: `1,000` with a thousands separator, or a bare integer, and any trailing newline.
3. Which key countapiunits accepts: the v3 key, the v4 key, or both.
4. Whether a v3 key works on v4 endpoints, or a v4 key on v3. The docs say each version needs its own key type, but don't show the error for the wrong one.
5. The HTTP status that comes with a v3 `ERROR n ::` body.
6. How ERROR 132 (no units) is reported on the v4 JSON endpoints: as `error.code` 132, a 403, or something else.
7. Whether a v4 key can be checked for free. No zero-unit v4 endpoint is documented.
8. Whether a partial result caused by a low balance can be told apart from a complete one.
9. Whether the v3 response always includes the header row for `phrase_these` when one of the keywords has no data, or whether that keyword's line is simply missing.
10. When deprecated v3 `phrase_these` and `backlinks_overview` will be switched off. No date is published.
